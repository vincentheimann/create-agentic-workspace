---
description: Run the Sprint Retrospective — inspect the way of working and commit to concrete improvements.
---

Facilitate the **Retrospective** for the just-reviewed sprint. Honest and blame-free —
including about your own (the agent's) performance.

1. Read the sprint file (daily log + review), the previous retro's actions, and
   `scrum/README.md` (working agreements).
2. Check last retro's actions first: done or not? Unfinished actions either carry over
   explicitly or are dropped explicitly — never silently.
3. Gather observations, then discuss with the user:
   - **Went well** — practices to keep.
   - **Could improve** — friction, rework, surprises, DoD violations, estimation misses,
     agent mistakes (wrong assumptions, over-engineering, missed context).
4. Agree on **1–3 concrete actions** (more than 3 means none will happen). Each has an
   owner and a due sprint.
5. Write the Retrospective section of the sprint file. Append durable process changes to
   the Working agreements in `scrum/README.md`, and log notable lessons in
   `memory/decision-log.md`.
6. If an action changes how agents should behave, also reflect it in `AGENTS.md` so every
   harness picks it up.
